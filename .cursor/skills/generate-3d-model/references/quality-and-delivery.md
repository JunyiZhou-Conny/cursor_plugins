# 验收与交付：把“完成了什么”说准确

## 分层证据

| 层级 | 实际做什么 | 不能因此声称 |
|---|---|---|
| Q0 服务产出 | 结果回读无错误，存在真实本次模型地址 | 已下载、已显示、已验收 |
| Q1 文件归档 | 文件非空、大小/文件头合理、保存 SHA256 | 网格无洞、贴图完整、官方 hash 一致 |
| Q2 结构/格式 | 清点节点/材质/动画/资源，再用正式验证器检查 | 模型好看、脸像、手指正确 |
| Q3 视觉 | 同光照下看正/斜/侧/背与灰模，记录截图/视频 | 目标网页的加载速度/可访问性达标 |
| Q4 应用 | 在用户目标环境实际加载交互，按需求测量 | 其他设备/打印/全身动画也通过 |

每项填写 pass/fail/not_run/not_applicable + 实际证据文件；验收范围比通过标签更重要。
本包 `inspect` 仅清点 GLB JSON，完整结构验证可用 Khronos glTF Validator [S12]；勿偷换名称。
它统计的是 accessor 元数据声称的数量，不解码压缩几何，不计算真实拓扑或场景实例化总面数。

## 视觉检查看什么

人物：五官比例、脸/脖深度、眼口衔接、牙齿、头发体积、手指融合、半身底部收口、侧背异常。
物件：整体比例、关键部件位置、连接/悬空、薄壁和穿插、背面、材料分区。
灰模揭露几何，带贴图模型体现最终观感；两者都重要。
参考图对照须同姿态/近似视角，不把角度变化产生的差异误判成脸变了。
必须从真实网格渲染，不可用图像模型生成“更好看的模型预览”冒充证据。
审美可以主观，注明是用户/agent 的判断；不要生成虚假的身份识别置信度。

## 减面与网页优化

保留 original；改变输出为 web_v1/web_v2。先测后改，不用固定三万面或 5MB 一刀切。
减面若破坏 UV/法线/材质，可能要重烘焙；先生成高模贴图再减面并非总是最省成本。
如果生产用途早已明确，可以在贴图前规划拓扑；本 skill 的“先原稿”只是探索型选择。
压缩算法/纹理格式要和加载器一起验证；文件更小但打不开不算成功。
静态头像的关键体验还包括加载占位、失败回退、可减少动画和手机构图；不要盲开昂贵后期。

## 每次运行的输出契约

`HANDOFF.md` 记录问题、选择、实际执行、版本、验证、不足与下一步。
`NEXT_AGENT_PROMPT.md` 必须足够自包含：输入位置、当前结果、现存 request ID、预算权限和第一个动作。
`ASSETS.json` 包含真实 URL 和计划存储位置；`PACKAGE_MANIFEST.json` 只陈述实际 ZIP 内容。
`DOWNLOADS.html` 按本地已入包 / remote-only / missing 标注，不许把未来路径做成下载承诺。
模型文件与参考图/服务预览/纹理 atlas 角色不同，名字中注明用途。
下载前 SHA256 可未知；下载后计算的是本地 hash，除非服务真的给过 expected hash，不称“官方校验通过”。

## 被阻塞也要有可用交接

已有远程 GLB 但网络禁止下载：交付真实 URL、request ID、远程清单与恢复指令，ZIP 名称写“docs-and-references”而非“complete-model”。
只拿到图片而无成功任务：写 reference-only，不能叫 3D model delivered。
无渲染工具：不要停留在虚假的审美判断，交付模型与未验收项，给下位 agent 明确检查动作。
没有权限/凭据不等于产品不支持；当前环境缺口与产品能力分开。

## 可重用与项目私有要分开

Skill 包只存方法、模板、合成测试，不夹带用户照片/真实 CDN URL。
项目 handoff 按授权包含源参考，默认把真人源照片作为 private_reference 排除。
默认排除未知保密级别和 secret；凭据不应进入任何 handoff。
照片、生成肖像、模型和任务链接均可能识别用户，排除原照不是匿名化认证。
