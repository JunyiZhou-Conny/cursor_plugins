# 最初一次真实试作：提炼方法，不固化偶然设置

这是从 2026-09-17 对话与已读取交接文件归纳的案例，不是重新执行的实验。
来源：原会话的 `3D_Resume_Agent_Handoff.md`、`anime_character_v1_generation.json`、`3D_Resume_Next_Agent_Prompt.md`。
为便于分享，本 skill 不附这些私人项目原件，也不写照片、用户身份、仓库地址、request ID 或模型 URL。

## 已发生的结果

照片先形成动漫风格，再整理为白底建模参考。最终经 fal 的 Meshy 图转三维得到带颜色的静态人物，用户认可方向。
当时使用 `meshy/v7/image-to-3d`，已保存请求为：

```json
{
  "model_type": "standard",
  "should_remesh": false,
  "should_texture": true,
  "enable_pbr": false,
  "pose_mode": "",
  "enable_rigging": false,
  "enable_animation": false,
  "ultra_mode": false,
  "enable_safety_checker": true
}
```

真实 image_url 在项目私有记录，不在此示例中。
没有显式传目标面数、对称参数、额外贴图参考或贴图提示词。
服务报告 GLB 约 63.4 MB，仅完成服务正面预览检查；当时网络阻止输出落地，因此本地网格、多角度和网站验收未完成。
原稿成为后续网站开发的基础，不是已完成的 production 模型。

## 可复用的经验

| 现象 | 保留为规则 | 不应推广成 |
|---|---|---|
| 从模糊风格开始也能得到满意结果 | 先把风格变成可比较参考，再生成三维 | 用户必须会写专业 3D prompt |
| 动漫图有背景/自拍透视 | 分离探索图和建模图 | 所有人都必须重画成写实 |
| 讨论过的参数与最后执行不同 | 保存真实 payload，历史方案单列 | 用讨论内容补全未执行记录 |
| 受限上传做了 768×960 / AVIF q40 | 记录传输妥协，保留源图 | 压小图片是质量最优 |
| 多次轮询一个任务 | 存任务 ID，续跑同一任务 | 轮询次数等于付费生成次数 |
| 服务生成了大原稿 | 模型生成与网页优化分阶段 | 所有生成必须关闭 remesh |
| 结果存在但本地不能下载 | 链接/文档包与模型包分清 | 为下载问题再花一次生成费 |
| 用户满意现有 V1 | 保存并继承认可的形象 | agent 可无限重做直到自认完美 |
| 文档与查看页可交付 | 交接包含权限、证据与下一步 | 脚本语法过了就代表真实模型可加载 |

## 不能从一次案例得出的结论

没有进行跨模型肖像质量比较，没有验证全身动画/3D 打印路线，没有证明自动分离眼球，也没有证明这些参数适合一切艺术风格。
原案例预算是用户自述充值，不是已读账户余额或不限额支出授权。
本 skill 的价值是把选择、检查、恢复和交付做可靠，而不是保证每次 AI 网格都会完美。
