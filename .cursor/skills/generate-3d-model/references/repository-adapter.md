# 可选：从独立模型到网站场景

这份文件是接口检查的方法，不是让 agent 每次都修改某个固定仓库。
没有目标仓库则跳过。用户给 URL 时优先使用匹配的仓库连接器；先读再决定，不从记忆覆盖工作。

## 读取清单

README / 协作约定 → 资源加载代码 → 相机/动画使用位置 → UI 状态映射 → 压缩与纹理解码配置。
记录 repo、branch、commit（有就记）、文件路径与 blob SHA（有就记）；不能把文件 SHA 冒充 commit。
权限不包括修改/发布则只形成适配计划。已有并行工作先检查，不覆盖。

## 一个历史滚动简历模板的例子

最初案例的模板加载 `web/public/models/me.glb`，使用 `CameraAction` 驱动滚动镜头，按 `focus-*` 找焦点，并按名称包含 `eye` 找眼睛对象。
其首页接受 focus-start/focus-0，履历焦点和条目对应，作品区有回退；历史时间轴约定为 24fps、节点间隔 50 帧。
这来自最初项目交接里的已读仓库记录，**不是所有 GLB 的规则，也不是当前任何仓库的永久状态**。
下一次实际用到必须重新检查真实代码；不自动把五条履历作为不变要求。

可选两路：A) 导出符合模板契约的 GLB 场景；B) 修改网页代码控制镜头，把人物作为单纯资产加载。
采用哪条取决于最小安全改动，不默认使用某个付费编辑网站。
相机动画不是骨骼动画；时间轴以 24fps 解读也不意味着网页只能渲染 24fps。
把模型重命名 me.glb 只是路径改变，不会创造相机/锚点/独立眼睛。
眼球 mesh、旋转中心和局部轴必须真实合理；不能把整个头命名成 eye 来“满足检查”。

## 交付给网站 agent

说明资产版本/大小/坐标/前向/验证，列出场景需补的内容，以及是否允许改代码。
保留原稿，另导出 production 候选；加载/渲染/手机构图在真实目标环境测试。
构建、类型检查与浏览器检查分开记录；没有运行就写未运行。
原作者个人模型、文案、品牌图像的使用许可和代码许可分开；不要从示例简历编造用户履历。
