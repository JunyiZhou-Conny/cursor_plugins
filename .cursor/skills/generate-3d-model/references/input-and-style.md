# 从模糊愿望到适合建模的参考

## 1. 创意输入不是参数表

“可爱一点”可以提出一组可撤回解释：稍大头身比、圆润轮廓、简化面部、成束头发、柔和配色。
“像游戏角色”可以解释为更有体积的形体、清楚材质分区、不过度扁平的脸。
“黏土风”侧重圆润厚实、哑光表面和少量手作起伏；这些是风格提案，不是事实判断。
先写 3–5 个保留特征、2–3 个可调项及 1 个禁止改变项，再制图。
脸部相似度按用户目标判断：有时喜欢“气质像我”的卡通化，而不是严格肖像重建。

## 2. 风格探索与建模参考各有用途

探索图可以夸张、带背景和幽默元素；建模图则减少歧义，但应保留同一个角色。
两张图可以是一张：如果原图已经单主体、结构可读且用户喜欢，不做无意义的重绘。
不要为了满足“干净”把人物变成标准模板脸，或消除用户希望保留的表情和特殊比例。
复杂构图先删背景、理清外轮廓，再讨论是否简化手势；不随意删用户喜欢的手。

## 3. 参考图审核表

| 看什么 | 通过标准 | 修改方向 |
|---|---|---|
| 主体与边缘 | 有意的底部收口可接受；重要轮廓不被无意裁掉 | 扩展画布/重新构图，不只是给已裁切图加白边 |
| 视角 | 能清楚看脸/主要结构，透视符合想做的模型 | 减轻近大远小；不把所有对象都正交化 |
| 明暗 | 区分真实颜色与照明，没有大块强阴影遮结构 | 柔和光照；不用去阴影把鼻子彻底抹平 |
| 头发/细附件 | 发束轮廓可读，小结构有体积 | 选择性成组，不把每根发丝当独立细线 |
| 手/脸 | 手指关系、眼口结构、遮挡可理解 | 分离轮廓、减少挡脸；必要时局部修图 |
| 颜色 | 服装和肤色与用户选定风格一致 | 统一色板，避免新 logo/文字 |

这些检查结合官方输入建议 [S1/S2/S4/S6] 与本 skill 的审美判断；不存在保证一次成功的分数。
官方来源见 [official-sources.md](official-sources.md)。

## 4. 分辨率与文件路线

保留原始参考，优先支持良好的 PNG 或高质量 JPEG；透明图要检查边缘，白底也可以。
用足够清晰的图而非盲目提高像素。1024–2048 级可以是制图起点，不是必须正方形或强制尺寸。
主体占大部分画面并保留边距；70–90% 若使用，应标为经验构图范围，不当作官方硬指标。
先看上传能力、真实大小限制和像素限制，再决定缩放。不要因为聊天工具输入长度而牺牲细节。
图片重编码后记录真实尺寸、色彩处理、压缩质量、源和输入两份 SHA256；只有计算过的 hash 才写值。
AVIF 是可选传输格式，仅在所用接口支持时使用；不能把某次受限环境里的 q40 固化为最佳设置。

## 5. 多视图的选择题

有清楚的同风格正侧背图且几何复杂：评估多视图。
只有一张好图：先单图，别为凑数量合成互相矛盾的视图。
AI 补角度：建立锁定的角色描述，确保服装、发型、左右手、姿势一致，分别输出角度，不把四格拼图当单图上传。
所有补图属于设计假设；还原脸的背面从来不是“发现真相”。
从生成的 V1 渲染视图可用于检查/再风格化，但不是能纠正 V1 本身错误的新观测。
多图并非越多越好；按真实 schema 的数量和顺序提供。[S3]

## 6. 不把静态展示做成不必要的动画工程

半身像、手势、眨眼可以作为固定造型。A/T 姿只是动画分支的常见制作选择，不是所有模型门槛。
如果用户明确需要眼球、说话、表情：在 brief 标注独立编辑结构，而不是在 texture_prompt 里祈求实现。
初版无法自动得到独立眼球时，可以暂不启用该互动；变动表情仍须尊重用户选择。
